# YouTube 創作ストーリー動画 自動生成エージェント ロードマップ

「日本（日本人）の凄さ・日本の技術の凄さ」に注目した感動×スカッと系ストーリーを、
映像・朗読音声・BGM入りの約30分動画として自動生成し、YouTube投稿まで持っていくエージェントの全体設計。

---

## 0. 全体像（パイプライン）

```
[企画] → [プロット生成] → [台本生成] → [台本検品]
   → [朗読音声生成(TTS)] → [シーン分割・画像/映像生成] → [BGM選定]
   → [動画合成(タイムライン組立)] → [サムネ・タイトル・説明文生成]
   → [最終チェック] → [YouTubeアップロード] → [分析・改善ループ]
```

各工程は独立したモジュールとして作り、途中成果物（プロット、台本、音声、画像、動画）を
すべてファイルとして保存して人間がレビュー・差し替えできる構造にするのが基本方針。
最初から全自動を狙わず、「半自動＋人間の承認ポイント」から始めて段階的に自動化する。

---

## 1. フェーズ1：企画・設計（土台づくり）

### 1-1. チャンネル・コンテンツ設計
- ターゲット再確認：50〜60代男性、感動×スカッと、一気見できる分かりやすさ
- 今回のジャンル軸の定義：
  - 日本の職人技・製造技術・現場力（町工場、伝統工芸、インフラ、鉄道、造船 など）
  - 日本人の誠実さ・勤勉さ・matter-of-fact な仕事ぶりが海外や権力者を見返す構図
  - 「見下されていた日本の技術/人が、実力で世界や悪役を黙らせる」スカッと構造
- NG方針の明文化：排外的・他国貶めに寄りすぎない（炎上・収益化リスク回避）。
  「日本sugoi」ではなく「誠実な仕事が報われる」を軸に置く
- 1本の構成フォーマット決定：
  - 尺 約30分 ≒ 朗読 9,000〜12,000文字（読み速度 350〜400字/分想定）
  - 冒頭30秒のフック（離脱防止）、二部構成（起承転転結×2）、チャプター設計

### 1-2. 台本プロンプトの改修
- 既存プロンプト（感動×スカッと汎用版）をベースに「日本の技術・日本人の凄さ」特化版を作成：
  - 主人公候補：町工場の職人、伝統工芸士、鉄道整備士、造船技師、刀鍛冶、宮大工、
    半導体・精密加工の技術者、酒蔵の杜氏、農機具メーカーの開発者 など
  - 悪役候補：外資コンサル、買収を仕掛ける海外ファンド、コスト削減しか見ない経営陣、
    技術を盗もうとする競合、現場を知らないエリート など
  - 逆転手段候補：日本にしかない精度・品質が国際的な場で証明される、
    海外の大口顧客が職人を名指しする、匠の技が事故や危機を救う など
  - 「技術ディテールの見せ方」ルール追加：専門用語を使いすぎず、
    数字と比喩で凄さを伝える（例：「髪の毛の1/100の誤差」）
- ランダム化リスト（職業・舞台・逆転・結末）を日本技術版に差し替え
- 伏線カタログも「道具・工具・図面・銘・師匠の言葉」など日本もの向けに拡張

### 1-3. 技術スタック選定
- 台本生成：Claude API（プロット→台本の2段生成）
- TTS（朗読）：候補を比較検証
  - 日本語品質重視：にじボイス / VOICEPEAK / Azure TTS / Google TTS / ElevenLabs(日本語)
  - 30分朗読の安定性・価格・商用利用可否で選定
- 画像/映像生成：
  - 静止画＋Ken Burns（ズーム/パン）方式が現実的（画像生成：Midjourney/DALL-E/SD系）
  - 将来的に動画生成（Runway/Pika/Sora系）へ拡張
- BGM：フリー音源ライブラリ（DOVA-SYNDROME、Artlist等）＋シーン感情タグでの自動選曲
- 動画合成：ffmpeg または Remotion / MoviePy（プログラマブルに組めるもの）
- アップロード：YouTube Data API v3

**成果物：** 設計ドキュメント、特化版台本プロンプト、技術選定メモ

## 2. フェーズ2：台本生成モジュール

1. **プロット生成**：特化版プロンプトで約6,000字のプロットを生成（出力構成は既存ルール踏襲）
2. **プロット検品**：チェックリストで自動検査＋人間レビュー
   - 伏線と回収の対応が取れているか / 悪役の報いが具体的か / 大衆反転に納得感があるか
   - 連続使用回避（過去作品の職業・舞台・逆転手段をDB化して照合）
3. **本文（朗読台本）生成**：プロットから章ごとに分割生成（1回の生成で1〜2章、計10,000字前後）
   - 朗読用に整形：読み間違いやすい漢字のルビ/ひらがな化、会話主体、一文を短く
4. **台本検品**：文字数、禁止事項（無双しすぎ・ご都合主義等）、事実性（実在企業名・実在人物を避ける）

**成果物：** `plot.md` → `script.md`（章分割済み・TTS用整形済み）、過去作品DB（重複回避用）

---

## 3. フェーズ3：音声生成モジュール（朗読＋BGM）

1. 台本を段落単位でTTS APIに投げ、章ごとのWAV/MP3を生成
2. ポーズ制御：場面転換で1〜2秒の間、セリフの前後で微調整
3. 品質チェック：読み間違い検出（生成音声のSTT逆変換→台本と突合）、聞き直しポイントの人間確認
4. BGM設計：
   - 台本の各章に感情タグ（不遇/緊張/転機/逆転/感動）を付与
   - タグ→BGMライブラリのマッピング表で選曲、クロスフェードで接続
   - 朗読 -14LUFS前後、BGMは -25〜-30dB程度にダッキング（ffmpeg sidechaincompress）

**成果物：** 章別朗読音声、BGM付きミックス音声（約30分）、感情タグ付き台本

---

## 4. フェーズ4：映像生成モジュール

1. **シーン分割**：台本をLLMで30〜60シーンに分割し、各シーンに画像プロンプトを生成
   - キャラクター一貫性：登場人物ごとの外見定義（キャラシート）をプロンプトに固定挿入
   - 昭和〜現代の日本の工場・職人・街並みなど、世界観のスタイル指定を統一
2. **画像生成**：シーンごとに16:9画像を生成（1シーン30〜60秒表示 → 30分で約40〜60枚）
3. **動きの付与**：Ken Burnsエフェクト（ズーム/パン）、場面転換のフェード
4. **テロップ**：章タイトル、重要セリフの字幕（任意。50〜60代向けには字幕ありが有効）

**成果物：** シーンリスト（タイムコード付き）、画像セット、映像クリップ

---

## 5. フェーズ5：動画合成・パッケージング

1. タイムライン組立：音声の実尺を基準にシーン画像の表示時間を自動割付 → ffmpeg/Remotionでレンダリング
2. オープニング/エンディング定型パート（チャンネルロゴ、チャンネル登録誘導）
3. サムネイル生成：感情の強いシーン画像＋大きい文字コピー（LLMでコピー案を3〜5個生成し選択）
4. メタデータ生成：タイトル案（クリック率重視で複数案）、説明文、タグ、チャプター（タイムスタンプ）
5. 最終チェックリスト：音ズレ、音量、誤字、権利（BGM/フォントのライセンス）、YouTubeポリシー適合

**成果物：** 完成動画（mp4）、サムネ、タイトル/説明文/タグ/チャプター

---

## 6. フェーズ6：投稿・運用ループ

1. YouTube Data APIで予約投稿（人間の最終承認を挟むフローから開始）
2. 分析：YouTube Analytics APIで視聴維持率・CTR・コメントを取得
   - 離脱ポイントと台本構成の対応分析 → プロンプトの改善にフィードバック
   - コメントの感情分析で「スカッと度」「感動度」の受け止めを計測
3. シリーズ運用：過去作品DBで設定の重複を管理、当たり回のパターンを抽出して重み付け

---

## 7. 実装の優先順位（マイルストーン）

| MS | 内容 | ゴール |
|----|------|--------|
| M1 | 特化版台本プロンプト＋プロット→台本生成（手動実行でOK） | 1本分の台本が完成する |
| M2 | TTS選定・朗読音声パイプライン | 30分の朗読音声ができる |
| M3 | 画像生成＋ffmpeg合成（静止画スライドショー＋BGM） | 1本目の動画が手動投稿できる |
| M4 | 各工程のスクリプト化・CLI統合（1コマンドで台本→動画） | 半自動パイプライン完成 |
| M5 | サムネ/メタデータ生成、YouTube API投稿 | 承認ボタンだけで投稿完了 |
| M6 | 分析フィードバックループ、重複回避DB | 継続運用体制 |

**まず作るべきはM1〜M3**。ここまでで「1本作って投稿し、反応を見る」ことができ、
パイプラインの各工程の品質課題（TTSの自然さ、画像の一貫性、テンポ）が具体的に見える。

## 8. リポジトリ構成（案）

```
story/
├── docs/               # 設計ドキュメント（本ファイル等）
├── prompts/            # プロット/台本/シーン分割/サムネコピー等のプロンプト
├── pipeline/
│   ├── plot.py         # プロット生成
│   ├── script.py       # 台本生成・整形
│   ├── tts.py          # 朗読音声生成
│   ├── scenes.py       # シーン分割・画像プロンプト生成
│   ├── images.py       # 画像生成
│   ├── bgm.py          # BGM選曲・ミックス
│   ├── render.py       # 動画合成
│   ├── thumbnail.py    # サムネ生成
│   └── upload.py       # YouTube投稿
├── assets/bgm/         # BGMライブラリ（感情タグ付きメタデータ）
├── db/                 # 過去作品DB（重複回避）
└── output/<video_id>/  # 動画ごとの成果物（plot, script, audio, images, mp4）
```

## 9. 主なリスクと対策

- **TTSの不自然さで離脱** → 最重要。M2で複数エンジンをABテスト。人名・専門用語の読み辞書を整備
- **画像のキャラ不一致** → キャラシート固定＋シード固定。顔アップを避けた構図でごまかす手も有効
- **YouTubeのAI生成コンテンツポリシー/収益化基準** → 「大量生産的・反復的」と判定されないよう、
  台本品質と1本ごとの独自性（重複回避DB）を担保。AI生成の開示設定に対応
- **実在の企業・人物との類似** → 台本検品で固有名詞チェックを必須化
- **BGM・フォントの権利** → 商用利用可ライセンスのみをassetsに登録し、メタデータで管理
