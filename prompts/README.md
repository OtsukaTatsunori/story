# 台本生成システムの使い方

「王道の骨格は固定、中身は毎回違う」を機械的に保証するための組み立て式プロンプトシステム。

## 仕組み

```
banks/*.json（要素バンク）
      │  ランダム選択 + 履歴(db/history.json)で直近使用を除外
      ▼
pipeline/generate_prompt.py
      │  master_plot_prompt.md の {{スロット}} に差し込み
      ▼
完成プロットプロンプト → Claude → プロット(約6000字)
      │  人間レビュー・承認
      ▼
script_prompt.md + 承認済みプロット → Claude → 朗読本文(約10,000字、4分割生成)
```

## 手順

```bash
# 1. 今回のエピソードのプロンプトを生成（選択結果はdb/history.jsonに記録される）
python pipeline/generate_prompt.py --out output/ep001/plot_prompt.md

# 組み合わせを見るだけ（記録しない）
python pipeline/generate_prompt.py --dry-run

# 2. 出力されたプロンプトをClaudeに投げてプロットを得る → output/ep001/plot.md に保存
# 3. プロットを人間がレビュー（下のチェックリスト）
# 4. script_prompt.md + プロットで本文を4分割生成 → output/ep001/script.md
```

## 多様性の担保方法

- **要素の直近除外**: 職業は直近8話、逆転手段は直近7話、感動/スカッとパターンは直近6話…と
  スロットごとのウィンドウで使用済みIDを除外（`generate_prompt.py` の `SLOTS` で調整可）
- **組み合わせの重複回避**: 感動パターン×スカッとパターンの組は全期間で重複させない
- **伏線の型**: 18種から毎回4種を指定。同じ「型」でも中身はLLMが毎回創作する
- **バンクの育成**: 反応が良かった回の要素は残し、飽きられた要素は入れ替える。
  バンクのJSONに項目を足すだけで多様性が増える設計

## プロット検品チェックリスト（人間レビュー用）

- [ ] 冒頭30秒フックに「この後どうなる？」の引きがあるか
- [ ] 主人公の技術の凄さが数字・比喩で具体化されているか（説明になっていないか）
- [ ] 悪役の暴言は十分露骨か／制裁は目に見える形か／惨めなシーンが続くか
- [ ] 伏線4種がすべて張られ、すべて回収されているか（対応表が成立するか）
- [ ] 一つ目の転と二つ目の転が違う役割になっているか
- [ ] 大衆の反転に納得できる積み上げがあるか
- [ ] 「格上の第三者が認める」場面があるか
- [ ] 排外的表現・実在企業/人物/国への攻撃がないか
- [ ] 読後感4点セット（よくやった／報われた／スカッと／胸が熱い）が揃うか

## ファイル構成

| ファイル | 役割 |
|---|---|
| `master_plot_prompt.md` | プロット生成の骨格プロンプト（スロット入りテンプレート） |
| `script_prompt.md` | プロット→朗読本文の生成プロンプト |
| `banks/protagonists.json` | 主人公の職業・技能（25種） |
| `banks/villains.json` | 悪役の立場と手口（15種） |
| `banks/stages.json` | 舞台（15種） |
| `banks/reversals.json` | 逆転のきっかけと手段（18種） |
| `banks/endings.json` | 結末の形（12種） |
| `banks/relations.json` | ヒロイン/味方/裏切り/大衆反転/転機① ② |
| `banks/kando_patterns.json` | 感動パターン（15種） |
| `banks/sukatto_patterns.json` | スカッとパターン（14種） |
| `banks/foreshadowing.json` | 伏線の型（18種、毎回4種指定） |
| `banks/hooks.json` | 冒頭フックの型（8種）＋タイトル文法 |
| `../db/history.json` | 使用済み要素の履歴（自動生成・自動更新） |
